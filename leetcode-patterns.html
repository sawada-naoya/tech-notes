図解アルゴリズムパターン
問題を見た瞬間にパターン判定する

目指す状態は1つ。問題文を読んだ瞬間に「これは○○パターン」と判定できること。
コーディング面接で落ちる原因は「アルゴリズムを知らない」ことではなく、「知っているパターンを、目の前の問題に結び付けられない」ことである。だからこの教材は「問題文のどの言葉が、どのパターンのシグナルか」を中心に構成する。

主張1

パターンは20個もない。実務的な面接で出るのは14〜19個。それぞれに「判定シグナル」と「テンプレート」を1組で覚える。

主張2

テンプレートの暗記より「成立条件」の理解が重要。Two Pointers 型1 は「ソート済み」が前提。前提を確認せず適用すると、偶然当たるだけで保証がない。

主張3

同じ問題に複数のパターンが使えることが多い。「2値の和=k」はTwo PointersでもHashMapでも解ける。計算量で選ぶ理由を言えることが評価される。

00 はじめに — これは「判定」の問題

結論。アルゴリズム問題を解く作業は、3ステップに分解できる。多くの人が詰まるのは1番目であり、そこは才能ではなくパターン認識の訓練で解決する。

①ができないと②③に進めない。 そして①の訓練とは「問題を解く」ことではなく「問題文のシグナルを言語化すること」。解いた問題を必ず「何がシグナルだったか」で振り返る。

図0-1 3ステップ。①判定が最も難しく、最も訓練で改善する。

Part 1

配列・文字列

最も出題頻度が高い領域。Two Pointers（3型）・Sliding Window・Prefix/Suffixの5つで、配列問題の7割がカバーできる。重要なのは各パターンの「成立条件」 — 特にTwo Pointers 型1の「ソート済み」を確認せずに適用するのが最も多い誤り。

01 Two Pointers 型1 — 両端から内側へ

使う場面: ソート済み配列・回文・合計系・文字交換。成立条件を2つ満たす必要があるので、まずそこを確認する。

図1-1 型1の動き。「片側だけ動かす」理由は、飛ばしたペアが後で使えるかもしれないから。

補足 — Two Pointers か HashMap か

「2値の和 = k のペア数」系は、ソート不要の HashMap 補数カウント（O(n)）の方が定石。Two Pointers はソートコストの分 O(n log n) になる。ただし Two Pointers は O(1) 空間なので、「O(1)空間」の制約があるなら Two Pointers。面接では「両方あります。制約次第でこちらを選びます」と言えるのが最良。

判定シグナルまとめ（型1）

  • 「両端から」「前後から」「2つの値を比較」という言葉
  • ソート済み配列で合計・差を求める問題
  • 回文（palindrome）の判定
  • 「対応する要素を交換する」（母音・大文字小文字）
  • 実例問題: Two Sum II (167), Valid Palindrome (125), reverseVowels (345), Max Number of K-Sum Pairs (1679), Container With Most Water (11)

02 Two Pointers 型2 — fast/slow（読み書きの分離）

使う場面: 条件を満たす要素を前に集める・満たさない要素を後ろに追いやる。left が「書き込み位置」、right が「読み取り位置」という役割分担が本質。

図2-1 型2の動き。「leftの左側は確定済み」という不変条件が正しさの根拠。

判定シグナルまとめ（型2）

  • 「ゼロを末尾に移動」「重複を除いた配列を返す」「in-placeで除去」
  • 「新しい配列を作らずに（O(1)空間で）整える」という制約
  • left が「書き込み位置」、right が「読み取り位置」として役割が分かれている
  • 実例問題: Move Zeroes (283), Remove Duplicates from Sorted Array (26), Remove Element (27), Sort Colors (75)

03 Two Pointers 型3 — 2文字列同時走査

使う場面: 2つの文字列を別々のポインタで走査する。片方は常に進み、もう片方は条件を満たしたときだけ進む。

図3-1 型3の動き。「部分列」と「部分文字列」の区別が判定の鍵。

判定シグナルまとめ（型3）

  • 「s は t の subsequence（部分列）か」→ この型一択
  • 「順序を保ちながら一致を探す」「片方だけ進む」
  • 2つのソート済み配列のマージ・共通要素の抽出（同じ型の変形）
  • 実例問題: Is Subsequence (392), Merge Sorted Array (88), Intersection of Two Arrays II (350)

Two Pointers 共通の判定ヒント（3型まとめ）

型ポインタの動きシグナル前提
型1(a) 両端の対応両端 → 内側（両方動く）回文・文字交換なし
型1(b) 合計を探す両端 → 内側（片側だけ動く）「2値の和/差 = k」ソート済み必須
型2 fast/slow両方左から（役割が違う）「前に集める」「in-place除去」なし
型3 2文字列走査別々の列を進む「部分列か」「マージ」型3の一部でソート済みが必要

04 Sliding Window

使う場面: 部分配列・部分文字列の最大最小、条件を満たす「連続」部分。「連続」という言葉が最強のシグナル。

図4-1 Sliding Windowの2動作。「最長」と「最短」で記録のタイミングが逆になる点が最も間違えやすい。

判定シグナルまとめ

  • 「連続する〇〇の最大・最小」← 最強のシグナル
  • 「条件を満たす部分文字列（substring）」← substring は連続、subsequence は非連続（→ 型3 / DP）
  • 「長さ k のウィンドウ」（固定長）
  • 「最大でk回まで変更できる」（窓内の違反回数を数える）
  • 実例問題: Maximum Average Subarray I (643), Longest Substring Without Repeating Characters (3), Max Consecutive Ones III (1004), Minimum Size Subarray Sum (209), Permutation in String (567)

05 Prefix / Suffix（累積）

使う場面: 「自分以外の全要素の積/和」・除算禁止・O(n)制約、そして「区間の和を何度も問われる」。

図5-1 累積積。「左からの累積」と「右からの累積」の2パスで解く。

判定シグナルまとめ

  • 「自分以外の〇〇を求めよ」かつ除算禁止 → 累積積
  • 「区間の和を何度も問われる」→ 累積和（前処理してO(1)で答える）
  • 「累積和 + HashMap」で「和がkになる部分配列の個数」が解ける（Subarray Sum Equals K - 560）← 頻出の組み合わせ
  • 実例問題: Product of Array Except Self (238), Range Sum Query (303), Subarray Sum Equals K (560), Find Pivot Index (724)

Part 2

探索

Binary Search / BFS / DFS / BST。この4つで探索系の問題をカバーする。最も多い混同は「BSTの探索にグラフDFSのコードを持ち込む」こと。木・グラフ・BSTは似て見えるが、テンプレートが違う。

06 Binary Search

使う場面: ソート済み配列での検索、そして「答えで二分探索」（こちらの方が面接では難しく、差が付く）。

図6-1 2種類のBinary Search。②「答えで二分探索」が面接で差が付く部分。

判定シグナルまとめ

  • ソート済み配列で「〇〇を探せ」 → 基本形
  • 「最小の最大値」「最大の最小値」「〜できる最小のX」 → 答えで二分探索
  • O(log n) を要求されている → ほぼ二分探索（または木・Heap）
  • 「回転したソート済み配列」→ 二分探索の変形（どちら側がソート済みか判定する）
  • 実例問題: Binary Search (704), Search Insert Position (35), Find Minimum in Rotated Sorted Array (153), Guess Number (374), Koko Eating Bananas (875), Find Peak Element (162)

07 BFS（幅優先探索）

使う場面: 最短経路・最少ステップ・レベル順の探索・グリッドの探索。「最短」という言葉が出たらBFS一択（DFSでは最短が保証されない）。

図7-1 BFSは同心円状に広がる。「queueに入れる時にvisitedをマークする」が最重要。

判定シグナルまとめ

  • 「最短経路」「最少ステップ」「最小の手数」 → BFS一択
  • 「同時に広がる」「N分後にどうなるか」 → BFS（レベル順）
  • グリッド（2次元配列）の探索 → BFS または DFS
  • 「島の数」「連結成分の数」→ どちらでもよい（DFSの方が短く書ける）
  • 実例問題: Number of Islands (200), Rotting Oranges (994), Word Ladder (127), Binary Tree Level Order Traversal (102), 01 Matrix (542)

08 DFS 3パターン

DFSには「グラフ用」と「木用」の2系統がある。混同が最も多い。木には閉路がないので visited が不要で、ループも書かない。

図8-1 グラフと木の違い。木問題にグラフDFSのコードを持ち込むのが最も多い誤り。

判定シグナルまとめ

  • 「木の深さ・高さ」「全ノードを訪問」 → パターン③（木DFS）一択
  • 「全パスを列挙」「存在するか」 → DFS
  • グラフの全探索・連結成分 → パターン①②
  • BFSより実装が簡単なことが多い（最短でなければDFSでよい）
  • 実例問題: Max Depth of Binary Tree (104), Path Sum (112/113), Clone Graph (133), Number of Islands (200), Invert Binary Tree (226), Same Tree (100)

09 BST Search（二分探索木）

BSTの核心: 左 < 親 < 右 の順序保証を使って枝を切る。DFSやBFSは使わない（全探索する必要がないのに全探索するのは無駄）。

図9-1 BSTの探索。順序保証があるので、片方の部分木を丸ごと捨てられる。

判定シグナルまとめ

  • 「BSTで〇〇を探せ/挿入せよ」 → DFS/BFSは使わない。BST性質で枝刈りする
  • visited は不要（閉路がない・順序保証がある）
  • DFSのグラフコードと混同しやすい → graph[node] は存在しない
  • 「k番目に小さい」「昇順で取り出す」→ 中順巡回
  • 実例問題: Search in a BST (700), Insert into a BST (701), Validate BST (98), Kth Smallest Element in a BST (230), Lowest Common Ancestor of a BST (235)

Part 3

データ構造

HashMap / Queue / Linked List。「どのデータ構造を選ぶか」自体が解法になるパターン。特に Linked List は配列のテンプレートが一切流用できないので、別物として覚える。

10 HashMap

使う場面: 出現回数・「2つの値の組み合わせ」・O(1)検索。「O(n²) の2重ループを O(n) にする」ための最も一般的な道具。

判定シグナルまとめ

  • 「〇〇が存在するか」を高速に調べたい → HashMap（Set）
  • 「出現回数を数える」「アナグラム」→ 頻度カウント
  • Two Sum の変形（2値の組み合わせ）→ 補数を探す
  • 「グループ化する」→ 「何をキーにするか」を考える
  • 2重ループ O(n²) が思い浮かんだら、HashMapで O(n) にできないか疑う
  • 実例問題: Two Sum (1), Valid Anagram (242), Group Anagrams (49), Find the Difference of Two Arrays (2215), Max Number of K-Sum Pairs (1679), Contains Duplicate (217), Subarray Sum Equals K (560)

11 Queue（時間窓・スライディング記録）

使う場面: 直近N件・直近Nms以内のカウント・古いものを先頭から捨てる。「値が単調増加する」ことが前提（だから古いものは常に先頭にある）。

判定シグナルまとめ

  • 「直近〇〇ms以内」「直近〇件」→ Queue一択
  • 値が単調増加することが保証されている → 古いものは常に先頭にある
  • 先頭から捨てて末尾に追加 = FIFO = Queue
  • 「窓内の最大/最小」を効率よく求める → Monotonic Deque
  • 実例問題: Number of Recent Calls (933), Sliding Window Maximum (239), Moving Average from Data Stream (346)

12 Linked List

配列のテンプレートが一切流用できない。head[i] でアクセスできず、len(head) も使えない。prev / curr / next の3変数で1ステップずつ繋ぎ直すのが基本形。

図12-1 反転の動き。「next を先に保存する」のが唯一のコツ。

判定シグナルまとめ

  • 問題文に ListNode が出てきたら、配列のテンプレートは全部捨てる
  • 「反転」→ prev/curr/next の4行
  • 「中間点」「循環検出」「後ろからk番目」→ Fast/Slow ポインタ
  • 「先頭が変わりうる削除・挿入」→ Dummy Head（分岐が消える）
  • 実例問題: Reverse Linked List (206), Merge Two Sorted Lists (21), Linked List Cycle (141), Middle of the Linked List (876), Remove Nth Node From End (19), Odd Even Linked List (328)

Part 4

数値・選択

Bit Manipulation は「知らないと出てこない」系なので公式を暗記する。Greedy は「成立するかの判断」が本質で、テンプレートは自明。

13 Bit Manipulation

使う場面: 各ビットの状態を利用・DPで前の結果を再利用・O(1)空間の制約。「知らないと出てこない」ので公式として覚える。

図13-1 2つの公式と基本操作。x & (x-1) は「2のべき乗判定」「ビット数カウント」の両方に使える。

判定シグナルまとめ

  • 「0〜nの各数の1ビット数を求めよ」→ 右シフトDP一択
  • 「全要素が2回ずつ出現し、1つだけ1回」→ XOR一択
  • 「O(n)時間・O(1)空間」の制約がついたら即ビット演算を疑う
  • 「2のべき乗か」「ビット数」→ x & (x-1)
  • 「部分集合の全列挙」（n ≤ 20）→ ビット全探索（for mask := 0; mask < 1<<n; mask++）
  • 実例問題: Counting Bits (338), Single Number (136/137), Missing Number (268), Number of 1 Bits (191), Power of Two (231), Subsets (78)

14 Greedy（貪欲法）

使う場面: 「今できるなら今やる」で最適解が得られる問題。テンプレートは自明。難しいのは「Greedyで正しいのか」の判断。

④ Greedy が成立する条件（最重要）

条件: 局所最適 = 全体最適

「今の時点で最善の選択が、最終的にも最善である」ことが証明できる必要がある。これが成立しない問題にGreedyを使うと、テストケースは通っても間違っている。

成立する例: 区間スケジューリング

「終了時刻が最も早い会議を選ぶ」→ 残り時間が最大になるので、常に最善。交換論法で証明できる（最適解の最初の会議を、終了が最早のものに置き換えても悪化しない）。

成立しない例: ナップサック問題

「価値/重量比が最大のものから詰める」→ 分割できないなら最適にならない。DPが必要。「分割可能ならGreedy、不可能ならDP」が有名な境界。

判断の実務的な手順

①小さな反例を探す（3〜4要素で試す）②見つからなければGreedyで進める ③面接では「この問題は交換論法でGreedyが最適だと示せます」あるいは「反例が見つからないのでGreedyを試します」と言う。黙って書くよりも、判断過程を説明する方が評価される。

判定シグナルまとめ

  • 「最大何個の〇〇を求めよ」で、順番に判定できる
  • 「最小の回数で」「できるか判定せよ」（到達可能性）
  • ソートしてから貪欲に選ぶ問題（区間・締切・コスト）
  • DPで書けるがO(n²)になる → Greedyで O(n) にできないか疑う
  • 実例問題: Can Place Flowers (605), Jump Game (55/45), Non-overlapping Intervals (435), Gas Station (134), Assign Cookies (455)

Part 5

次に覚える5つ

ここまでの14パターンで多くの Easy/Medium はカバーできる。次に投資すべきは Heap / Monotonic Stack / Backtracking / Union Find / DP の5つ。この5つを足すと Medium のカバー率が大きく上がる。各章はテンプレートと判定シグナルに絞る。

15 Heap / Priority Queue

使う場面: 「上位k個」「k番目に大きい」「常に最小/最大を取り出す」。Goには container/heap があるが、インターフェース実装が必要でボイラープレートが多い — テンプレートとして丸暗記する。

判定シグナルまとめ

  • 「上位k個」「k番目に大きい/小さい」→ サイズkのヒープ（O(n log k)）
  • 「常に最小/最大を取り出して処理する」→ Heap（Dijkstra・タスクスケジューリング）
  • 「中央値をストリームで求める」→ 2つのヒープ（最大ヒープ + 最小ヒープ）
  • 「マージするリストがk個ある」→ Heapでk-way merge
  • 全体をソートする必要がないのに sort している → Heapで速くなる可能性
  • 実例問題: Kth Largest Element (215), Top K Frequent Elements (347), Merge k Sorted Lists (23), Find Median from Data Stream (295), K Closest Points (973)

16 Monotonic Stack

使う場面: 「次に大きい要素」「直近の小さい要素」「ヒストグラムの最大長方形」。発想は「自分より小さい過去の値は、もう答えになれないので捨てる」。

図16-1 Monotonic Stack。「もう答えになれないものを捨てる」ので、各要素は最大1回popされる。

判定シグナルまとめ

  • 「次に大きい/小さい要素」「何日後に暖かくなるか」
  • 「ヒストグラムの最大長方形」「雨水を貯める」（両側の壁を探す）
  • 「各要素について、条件を満たす最も近い要素」を O(n²) で探そうとしたとき
  • 実例問題: Daily Temperatures (739), Next Greater Element I/II (496/503), Largest Rectangle in Histogram (84), Trapping Rain Water (42), Remove K Digits (402)

17 Backtracking

使う場面: 「全組み合わせ」「全順列」「条件を満たす全パターン」。骨格は「選ぶ → 進む → 戻す」の3行。

判定シグナルまとめ

  • 「全ての組み合わせ/順列を列挙せよ」「条件を満たす全パターン」
  • 「n ≤ 10〜20」という小さい制約（指数時間が許される）
  • 数独・N Queens・迷路の全経路
  • 「何通りあるか（個数だけ）」ならDPの方が速い（列挙が不要なら列挙しない）
  • 実例問題: Subsets (78/90), Permutations (46/47), Combination Sum (39/40), Word Search (79), N-Queens (51), Letter Combinations of a Phone Number (17)

18 Union Find（素集合データ構造）

使う場面: 「グループが同じか」「連結されているか」を、辺が動的に追加される中で問われる。DFS/BFSは「その時点のグラフ全体」を走査するが、Union Findは「繋がりを incrementally に管理」する。

判定シグナルまとめ

  • 「2つが繋がっているか」を何度も問われる（動的に辺が増える）
  • 「連結成分の数」を求める（DFSでも解けるが、Union Findの方が簡潔なことがある）
  • 「閉路があるか」の判定（Union が false を返したら閉路）
  • 最小全域木（Kruskal法）
  • 実例問題: Number of Provinces (547), Redundant Connection (684), Accounts Merge (721), Number of Islands II (305), Graph Valid Tree (261)

19 DP（動的計画法）

最後にして最大の山。DPは「同じ部分問題を繰り返し解くのをやめる」ための道具。3ステップ（状態定義 → 遷移式 → 初期値）を書き出せば、コードは自動的に決まる。

図19-1 DPの3ステップ。「状態定義」を日本語で1文書けるかが分岐点。

判定シグナルまとめ

  • 「何通りあるか」「最大/最小の合計」+ 選択の連続
  • 「部分列（subsequence）」（連続でない）→ DP（連続なら Sliding Window）
  • 再帰で書いたら同じ引数で何度も呼ばれる（重複部分問題）→ メモ化 or ボトムアップDP
  • Greedyで反例が見つかった → DP
  • n ≤ 5000 で O(n²) が許される制約 → 2次元DPの可能性
  • 実例問題: Climbing Stairs (70), House Robber (198), Coin Change (322), Longest Increasing Subsequence (300), Longest Common Subsequence (1143), Edit Distance (72), 0-1 Knapsack, Unique Paths (62)

学習の進め方（実務的な提案）

  1. 1問を3回書く > 3問を1回ずつ解く — テンプレートは反復でしか定着しない
  2. 解いた後に必ず「何がシグナルだったか」を1行書く — これが判定力の訓練そのもの。この教材の判定表に自分で追記していく
  3. 解けなかった問題は、答えを見た後に「翌日もう1回自力で書く」 — 見て理解した気になるのが最大の罠
  4. 計算量を必ず口に出す — 面接では「動く」だけでは不十分。O(n) と言えることが評価される
  5. エッジケースを自分から挙げる — 空配列 / 1要素 / 全部同じ / 負の数 / 最大値
  6. Part 5 の5パターン（Heap/Monotonic Stack/Backtracking/Union Find/DP）に投資する — Mediumのカバー率が最も上がる
